# 记忆与恢复

在多阶段任务、需要跨会话继续、关键决策形成或上下文即将切换时使用。记录能帮助下一位 Agent 恢复工作的事实；不要把完整聊天和反复思考堆进文件。

## 记录位置与负责人

先读取项目已有的状态、实验、设计或决策记录，复用现有格式。没有合适位置且确需持久化时，使用当前环境支持的持久存储；例如在获准修改的项目内建立 `docs/team/STATE.md`，有内容时再分出 `DECISIONS.md` 和 `LEARNINGS.md`。

没有文件或持久存储工具时，在交付中提供可复制的交接摘要，明确它没有自动保存。遵守当前环境的保存规范。不要仅因能看到某个位置就认为有权写入，不保存密钥或与任务无关的私人信息。

由 Steward 或指定的组织者统一维护索引与状态。其他 Agent 回传增量，不并行覆盖同一份记录。已有记录与当前产物冲突时，查证后更新，并保留重要决策变更的原因。

## 项目状态模板

只填写有意义的字段；一个小任务可以用一个段落。

```text
当前目标 / 已授权范围：
更新时间 / 对应产物或基线版本：
已完成：任务、产物、证据入口
进行中：任务、负责人、依赖、最后可确认状态
阻塞：原因、已完成的调查、解除所需条件
验证状态：通过 / 失败 / 受阻 / 未执行，分别对应哪个版本
下一步：下一个可执行动作、负责人、验收条件
重要资源：写入归属、仍在运行的任务和设备占用
需保留的用户决定与约束：
```

不要把“计划执行”记成“已经完成”。真实任务 ID 和存活状态来自工具；上下文恢复后重新确认，不假设旧 Agent 仍在运行。

## 决策记录模板

```text
问题与决策时间：
当时目标 / 约束 / 输入版本：
备选方案与选取结果：
关键证据与证据适用范围：
取舍和仍保留的异议：
决定者：
失效或重新评估条件：
```

只记录会影响后续行为的决定。普通实现细节无需逐一建档；用户批准、尚未获批和团队内部可撤销选择必须分清。

## 经验记录模板

```text
问题 / 可复现触发条件：
实际原因或当前假设：
有效处理 / 失败尝试：
证据入口 / 产物版本 / 环境：
证据状态：已验证事实 / 有依据的推断 / 待检验假设
适用边界 / 反例：
建议复用方式 / 应重新验证的条件：
```

记录失败的条件，避免将“这次无效”泛化为“永远无效”。保留负结果，不为让经验显得完整而编造因果。新证据推翻旧结论时标记其已失效或被替代，避免后续 Agent 继续引用。

## 里程碑复盘

在阶段完成、重要失败、反复调试或上下文切换时，检查：

1. 哪些工作确实改善了用户关心的结果？
2. 哪些假设被支持或推翻？
3. 哪类问题重复出现，是否需要改变方法？
4. 现有方向是否仍是满足目标的简单方案？
5. 哪些建议属于当前范围，哪些只能进入后续候选？

只形成短小的状态更新、决策变更或待验证建议。需要时提交 Architect 与 Researcher 重新评估。简短承认阶段成果即可，不生成拟人化茶歇或虚构团队活动。

## 恢复工作

1. 读取最近状态、当前有效决策和与任务相关的经验；不要全量加载所有历史。
2. 对照真实产物、版本、工具状态和用户的新指令核对记录。
3. 检查进行中任务是否还在运行、资源是否仍被占用，避免重复派工。
4. 处理过期证据与失效约束，只重开受影响的验收。
5. 更新任务契约，从下一个可执行动作继续。

使用已有事实恢复上下文；缺失的关键决定应查证或询问，不能自行补成历史事实。
